Consumption notes

This is not a fault report. It lists stretches whose usage sat far outside that category's own recent baseline — in either direction. A near-zero day usually means nobody was home, or the day simply broke routine; a high day might be EV charging, guests, or a cold snap. The data is correct in all of those cases. Where a headcount is logged under Occupancy in Settings, it's shown alongside as a hint. Nothing here can be deleted — only marked as reviewed. Not run automatically.

Consecutive days are grouped into one entry, so a fortnight away reads as a single note rather than fourteen. Only the range selected below is listed — it is the same range the charts on the other tabs use, so narrowing it there (or dragging across a chart) narrows this too. Covers what the household actually drew: grid import, gas and water. Solar export and battery charge/discharge are deliberately not listed — export is what was left over rather than something used, and battery flow is the same energy counted on its way past, so both track the weather rather than anything you did. Neither is unmonitored: both are still checked in full under Data health.

Compare calendar quarters

Q1 is January–March, Q2 April–June, Q3 July–September, Q4 October–December. Power, gas, water, solar, cost, battery, average headcount and the weather (average temperature and heating degree days, base 18 °C) are totalled per quarter. Cost is energy only: fixed or standing fees are not included, and water has no cost.

Tariff rate document (PDF)

Upload your supplier's rate specification PDF — rate periods are extracted and added to the rate schedules automatically. Recognized today: Vattenfall ("Tarievenspecificatie" and "Tarievenblad"), Greenchoice, Pure Energie, Innova Energie, Mega Energie, and Clean Energy all publish a downloadable rate sheet — get it from their website. Eneco and Budget Thuis don't — open their Modelcontract page and use your browser's "Print → Save as PDF" instead; Budget Thuis also needs its rate section expanded first (see the ⓘ for exact steps). Other suppliers aren't supported yet — use the CSV template below, or manual rate entry under Settings → Rates.

Data freshness

Most recent date with real data, per category. Costs Power/Gas show the latest rate period's end date instead — the boundary past which Costs falls back to a carried-forward stale rate.

Data integrity

Checks whether the stored data can be trusted — not whether your usage was unusual. Two passes: missing days, where an ingest path stopped silently partway through (distinct from "not tracked yet" before a device existed, and from staleness, covered by Data freshness above); and integrity findings — meter resets, corrected sensor glitches, two sources disagreeing about the same day, and physically impossible values such as a battery charge outside 0–100%. Everything here points at an instrument or ingest fault, so a finding is worth explaining. Days where consumption itself looked unusual are not faults and live under Consumption notes on the Comparison tab. Not run automatically.

Integrity findings

Totals reconciliation

Every other check on this page looks for something that seems odd. This one proves the arithmetic. On a cumulative meter a day's usage is simply the closing reading minus the opening one, so each stored daily total is re-derived that way — a completely different route to the same number — and compared. A summation bug cannot hide in both. Dates where the rollup deliberately drops an interval (a meter reset, or a gap longer than 26 hours) are reported as unverifiable rather than counted as passes, and today is skipped because it is still in progress. Not run automatically.

Fiscal year start ("1y" button)

Controls what date range the "1y" preset resolves to on each tab (start of the configured fiscal year through today). Water defaults to the calendar year; Power and Gas default to the Dutch utility billing year (1 May).

Feature toggles

The local device API is the live real-time poller (power/gas/water/battery) — checked once per poll cycle, so toggling it off takes effect within seconds, not just on next restart.

Dashboard visibility

Hide a tab if you don't have that device — Power always shows (every OmniMeter install has a P1 meter). Gas/Water/Battery apply to the tab navigation and the Overview tiles/Sources list; Self-Sufficiency (solar) applies to its own tab only, since it isn't part of the Overview tiles. Costs and Comparison are unaffected for now.

Occupancy

Headcount for a date range (you alone = 1, nobody home/away = 0). Each entry is the full headcount for its dates, not an addition to another entry, so log the new total every time it changes. Entries may overlap: a shorter entry nested inside a longer one wins for the days it covers, which is how a short trip taken during a long visit is recorded.

Leak alerts

Fast-path water-leak detection: watches for volume accumulated within an unbroken run of continuous flow, and pushes a Telegram message when it crosses a threshold. Turned on/off under Settings → Features (“Leak alerts”); requires OMNIMETER_TELEGRAM_BOT_TOKEN to be set in the environment (never shown here) — the chat ID below can be set from here instead of .env. The away threshold applies automatically once Away after (days) consecutive near-zero gas+water days have passed, unless an Occupancy entry (see the Occupancy tab) says otherwise.
